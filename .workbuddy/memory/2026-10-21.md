## 🎯 Strata q36 Bug #2（长 prompt 乱码）—— 根因修复完成

**根因**：`kv_half_bytes(kvm=0)` 缺 F32 分支，走了 int8 布局返回 264 B/cell，而 kernel 按 F32 1024 B/cell 读写 → **F32 KV 缓存少分配 4 倍**，kvh≥1 的全部 K/V 写越界落到相邻分配。ctx=32768 时 `kc[3]+(1*ctx+4096)*HD` **恰好 = S[4]**（GDN 状态），pos≥4096 后 K(kvh1) 写砸进 GDN 状态 → layer 4 起 router logits 粗大损坏（l2≈39）→ 乱码。

**定位路径（二分链）**（全部调试钩子已移除，方法记录备查）：
1. llama.cpp b11539 probe (8095) 建立真值：判据到 4137 全有效，margin 7.7-10.7 → 损坏是粗大的，非 1-ulp。
2. fullcmp 的「layer 0 即分叉」是 **warmup 污染 dump 的假象**（warmup 的 9-token chunk 落 pos 4095-4103；且 D 运行崩溃 dump 截断）——`--no-warmup` 重跑后干净。
3. 干净 D(T=2 walk) vs F(T=1) 对比：row 4095 layer 0-3 bitwise SAME，layer 4 分叉 → 病灶在 layer 4 内部。
4. 层内阶段二分（DUMPMID）：qkv/z/alpha/beta/hc 全 SAME，**gdn_y DIFF** → k_gdn_seq 输入异常。
5. **S_before（chunk2 入口的 S[4]）已 DIFF（l2=23）**；逐层入口探针：layer 0-3 入口干净、layer 4 入口被污染 → 写入者 = chunk 2 的 layer 3。
6. 层 3 内阶段探针：损坏出现在 k_attn_prep 之后（stage 20）；污染值 = K(kvh=1, cell 4096) **bitwise 相等**。
7. DMPTR 打印：`kc[3]+36MiB == S[4]` 逐字节相等 → 分配尺寸 bug 实锤。

**修复**（q36_engine.cu，一行）：`kv_half_bytes` 为 kvm==0 返回 `hd*4`。diff 收敛到 38+/1-：kv 修复 + Bug #1 tail-scale（d_tails/scale_gu_rows/scale_down_rows）+ 保留 DEBUG_MAX。

**回归**：全部曾 BAD 配置（T2walk c4095、T8walk c4096、T2seq c2048、decode n4098 c4090、long 4200）修复后 20/20 匹配文档真值；全文 4409 两种分块自洽。干净构建（7:16:39）复跑仍 ALL PASS。

### 追加澄清（13:48）：q4_0 为何没降总显存 + 并发为何不可行
- **用户观察「KV 用Q4 但总显存没降多少」成立，但归因要纠正**：实测 14654 → 15217 MiB（**涨 563 MiB**）。
  算账：q4_0 把 KV 从 2.92 压到 1.40 GiB（省 1562 MiB），但专家池从 1.45 涨到 3.31 GiB（多占 1905 MiB）
  ⇒ **省下的显存被主动拿去装27 个专家槽了**，命中率 8.1→24.5%、decode +10%。总占用本就应该涨。
- **剩余 834 MiB 物理上还能塞约 11 槽**（每槽 70.6 MiB），但 50 槽实测命中率反降 2.5pt
  ⇒ **瓶颈不是显存容量，是 first-use 准入策略的抖动**（slot replacement 1858 vs 1815）。
  再往上要么改准入策略，要么接受抖动。
- **🚨 Strata q36 不支持「多一路并发」**：`q36_engine.cu:1833` `per = kv_half_bytes(...) × n_head_kv × ctx × n_attn`
  **乘以 `n_sess`** ⇒ **每路并发一整份 KV，不共享不分片**；:1842 硬检查 `per × n_sess + 1GiB > free` 直接 `exit(1)`。
